## 背景

实习期间接手的小程序后端最初基于 PHP + FastAdmin 搭建，随着业务增长暴露出三个主要问题：

1. **接口风格不统一**：FastAdmin 自动生成的接口与手写接口混杂，前端联调成本高；
2. **业务逻辑分散**：大量逻辑堆积在控制器层，缺乏服务层抽象；
3. **版本管理缺失**：没有规范的分支模型与代码评审流程。

## 技术选型

选择 **Java 17 + Spring Boot 3** 作为重构目标栈，主要考虑：

- Spring Data JPA 能快速重建数据访问层，与原有 MySQL 表结构平滑对接；
- 团队后续有 Android 原生开发计划，Java 技术栈可以统一后端与移动端的技术语境；
- Spring 生态的过滤器与注解机制便于实现 RBAC 权限模型。

## 迁移策略

采用**渐进式迁移**而非一次性重写：

1. 先搭建 Spring Boot 工程骨架，按业务域划分模块；
2. 逐个业务模块迁移接口，新旧接口并行运行，通过网关层灰度切换；
3. 每个模块迁移完成后进行回归测试，确认无误再下线旧接口；
4. 数据层保持同库迁移，避免数据同步的额外复杂度。

## 工程规范建设

技术迁移之外，更重要的是建立可持续的协作流程：

- **GitLab 分支模型**：`main` 受保护，功能分支开发，合并必须走 Merge Request；
- **代码评审**：每个 MR 至少一人评审通过才能合入；
- **版本号规范**：语义化版本，完成了 v1.0.0、v1.0.82、v1.0.83 等核心版本上线。

## 结果与思考

重构完成后，接口响应性能与系统稳定性均有明显提升，新人上手成本显著降低。最大的体会是：**重构的价值一半在代码，另一半在流程**。没有流程保障的重构，很快就会腐化回原来的样子。
